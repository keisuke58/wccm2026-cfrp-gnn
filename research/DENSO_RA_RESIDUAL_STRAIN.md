## 2. やりたいこと（仕様）
**繊維強化樹脂を金型で成形したあとの残留ひずみを、機械学習で予測する。**

| | |
|---|---|
| 入力 | **結晶化度**、**繊維の向き** |
| 出力 | **残留ひずみ** |

### ★ここから確定すること（重要な読み取り）
1. **樹脂は半結晶性＝熱可塑で確定**。「結晶化度」が入力である以上、熱硬化エポキシではない
   （熱硬化に結晶化度は無い）。→ 構成則は **溶融→結晶化→冷却**。
   上位メモの要確認 11c（熱硬化か熱可塑か）は**これで解決**。
   ダイキン系 CFRTP と**同じ構成則の筋**に乗る（素材グレードは別物だろうが、物理の骨格は共通）。
2. **「繊維の向き」が入力かつ「樹脂を流す速さ」が調整対象**＝ **流動で決まる繊維配向**を扱う話。
   連続繊維の積層板（[0/90] のレイアップ角）ではなく、**射出／流動成形系の配向場**と読むのが自然。
   短繊維・長繊維の射出成形ならスキン-コア構造や配向テンソルの世界。**要確認だが、ここは設計に効く**。

### ★元メモの謎フラグメントが、ここで回収される
[`MEMO_nedo_jst_meeting_notes.md`](./MEMO_nedo_jst_meeting_notes.md) の原文断片のうち、意味不明として
保留していたものが**このテーマだった**と読める：
- 「**温度・きょう ＝ 結晶化 → 配向方向 → 密度**」＝ まさに本件の因果（温度履歴→結晶化度→配向→密度/収縮）。
- 「**条件：炭素繊維配向角**」＝ 入力の「繊維の向き」。
- 「**残留ひずみ場 → ひずみフリー（初期）/ 応力**」＝ 出力の残留ひずみ場（増分解析の初期状態から）。
- 「**Ansys 入れて simulation**」＝ 下記のデータ源。

## 3. データと方法
- **データは2種類**：
  1. **Ansys で計算したデータ**（＝シミュレーション側、量を作れる）
  2. **デンソーの実験データ（点で測ったもの）**（＝実測、**スパース**）
- **方法は転移学習の見込み**：Ansys データで学習 → 実験データで合わせる。**小島さんの研究に近い**。

### ★データ構造の含意（効いてくる点）
シミュは**場（フィールド）**、実測は**点**。つまり「**場で学習し、少数の点で較正する**」という形になる。
これは単なる fine-tuning ではなく、**スパース教師での場予測＋不確かさの較正**の問題。
→ 後述のとおり、本リポの conformal / UQ 系がちょうどこの形を扱っている。

## 5. 本リポの資産との対応（正直な棚卸し）

### ◎ 方法そのものが実物としてある：転移学習／sim2real
**先生が挙げた「小島さんの研究に近い」が、そのままリポにある**のが最大の一致点：
- [`tsa_sim2real.py`](../tsa_sim2real.py) — **小島さんの修論キャンペーン（2024年1月）の実測全場データ**
  （TSA＝熱弾性応力測定、320×255 の応力振幅マップ）を使い、**FEM と実測のドメインギャップを定量化**する。
  ＝ 本件の「Ansys で学習→実測で合わせる」と**同型**。
- [`kojima_real_case.py`](../kojima_real_case.py) / `kojima_real_conformal.py` / `kojima_real_decision.py`
  — 小島さんの実構造（CFRP 義足ソケット）での cross-geometry 検証・conformal・意思決定。
- 一般の転移：[`domain_adapt.py`](../domain_adapt.py)、[`conformal_transfer.py`](../conformal_transfer.py)、
  [`bootstrap_adapt.py`](../bootstrap_adapt.py)。
→ **転移学習の足場は作り直す必要がない。**

### ◎ スパース実測の扱い（点で測ったデータ）
conformal 系（`conformal_surrogate.py`, `conformal_emulator_uq.py`, `conformal_clearance.py` ほか）と
UQ 系（`uq_emulator*.py`, `decision_uq.py`）。**少数の実測点で予測区間を較正する**のが本来の用途なので、
「点で測った実験データ」という制約に正面から噛み合う。

### ◎ 場を出力する ML（残留ひずみ"場"が要るなら）
DeepONet の厚み方向残留応力サロゲート、メッシュ場サロゲート（平板・リング）、`mesh_agnostic_gnn.py`。
代表値でなく分布で求められても対応できる。

### ○ 結晶化の物理（入力の片方）
`cfrtp_residual_stress_fe.py`（結晶化度→収縮→残留応力/ひずみ）、Hoffman–Lauritzen / Nakamura の UMAT、
そして **`validation/cfrtp_peek_validation.py` は V1/V2/V3＋Tp バンド＋急冷しきい値まで検定済み**（2026-08）。
→ 「結晶化度」という入力変数の**物理的な妥当性チェック**ができる。ただし下記の注意を参照。

### ⚠️ 注意：本リポの FE は「データ源」ではない
データは **Ansys** で作る、と明言されている。つまり本リポの Python FE 群は**データ生成のクリティカルパスには乗らない**。
その価値は (a) 物理の理解、(b) **Ansys 結果の妥当性チェック**、(c) 必要なら補助的な合成データ生成、に留まる。
ここを「リポの FE が主役」と勘違いしないこと。**主役は ML と転移学習の側**。

### ✗ 穴：**流動で決まる繊維配向**（ここだけ無い）
本リポの「配向」は**積層板のプライ角**であって、**流動誘起の配向場ではない**。
検索して 0 件：**Folgar-Tucker / 配向テンソル / 射出成形**。
→ 入力「繊維の向き」をどう表現するか（配向テンソル a_ij か、主配向角＋異方度か、場かスカラーか）は
**新規に決める必要がある**。②の強度評価にも効くので、**最初に先方と合わせるべき仕様**。

## 8. 要確認（雇用手続きで資料が出たら）
- **素材系の具体**（PA/PPS/PP+GF/PEEK など）、繊維は炭素か**ガラス**か、短繊維/長繊維/連続繊維。
- **成形法**（射出か、圧縮/スタンピングか）＝「樹脂を流す速さ」の意味が変わる。
- **繊維の向きの与えられ方**：Ansys 側から配向テンソルが出るのか、角度スカラーなのか、場なのか。
- **残留ひずみの定義と測定法**：実験の「点」は何で測るか（ひずみゲージ／穴あけ法／DIC／X線）。
  **測定法によって何を予測すべきかが変わる**（表面か内部か、成分か等価量か）。
- **データ量**：Ansys 何ケース、実験何点か。転移学習の設計がこれで決まる。
